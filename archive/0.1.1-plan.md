# 0.1.1 — ring world + camera

Parent stage: `0.1.0-plan.md`. Scope: seeded ring layout with guaranteed node
spacing, a placeholder train, and a wrap-seamless side-view camera. No economy
tick, no prices, no hover labels, no kinematics — those are 0.1.2 / 0.1.3.

## World constants (const.js)

| name | default | meaning |
|---|---|---|
| RING_KM | 64 | ring length; `x` lives in `[0, RING_KM)` |
| NODE_N | 14 | nodes on the ring |
| RES_N | 3 | resources R1..R3 |
| MIN_GAP_KM | 2.5 | minimum wrap distance between any two nodes |
| SRC_BASE_MIN / MAX | 6 / 14 | source value-curve center, cr/unit |
| CON_BASE_MIN / MAX | 18 / 36 | consumer value-curve center, cr/unit |
| INFLOW_MIN / MAX | 0.04 / 0.12 | SRC emission, units/s |
| RATE_MIN / MAX | 0.02 / 0.08 | CON consumption, baskets/s |
| CAP_MIN / MAX | 60 / 140 | SRC yard capacity, units |
| CON_CAP_MIN / MAX | 40 / 100 | CON yard capacity per resource, units |
| SRC_STOCK_MIN / MAX | 0.3 / 0.6 | SRC starting stock, fraction of cap |
| CON_STOCK_MIN / MAX | 0.05 / 0.2 | CON starting stock, fraction of cap |
| K_MIN / MAX | 0.5 / 2 | price fragility `k_i` |
| TRAIN_V | 1.5 | placeholder train speed, km/s (visual) |
| CAMERA_FOLLOW | 2.5 | camera smoothing rate, 1/s |
| KM_VISIBLE | 26 | ring km spanned by the viewport width |
| TIE_KM | 0.5 | track tie spacing, km |

## Placement — guaranteed spacing

Divide the ring into `NODE_N` equal slots of `RING_KM / NODE_N` km. Put one node
in each slot at `slot * i + jitter` with `jitter ∈ [0, slot - MIN_GAP_KM]`.
Two nodes in adjacent slots (including the wrap pair across `x = 0`) are then at
least `MIN_GAP_KM` apart by construction: the worst case is the earlier node at
maximum jitter and the later node at zero. No rejection loop, `O(NODE_N)`, and
the guarantee holds for every seed, so `experiments/world.js` can assert it
over 100 seeds instead of hoping.

## World state (world.js, flat typed arrays)

```
x[i]           Float32Array(NODE_N)      ring position, km
kind[i]        Int8Array(NODE_N)        SRC = 0, CON = 1 (MIX is 0.1.7+)
need[i]        Int8Array(NODE_N)        CON recipe bitmask (1..2 resources)
rate[i]        Float32Array(NODE_N)      CON baskets/s
fragility[i]   Float32Array(NODE_N)      price curve exponent k_i
stock[i*3+r]   Float32Array(NODE_N*RES_N)  yard stock, units
cap[i*3+r]     Float32Array(NODE_N*RES_N)  yard capacity, units
inflow[i*3+r]  Float32Array(NODE_N*RES_N)  SRC emission, units/s
base[i*3+r]    Float32Array(NODE_N*RES_N)  value-curve center, cr/unit
```

Every node gets a yard and a base price for all three resources; a SRC emits
exactly one resource (one nonzero inflow), a CON stocks only its recipe
resources. Kinds are random with a fix-up guaranteeing at least one SRC and one
CON. Generation consumes the shared seeded RNG in a fixed order, so the same
seed always yields the same world.

Helpers: `World.wrap(x)` (into `[0, RING_KM)`), `World.distance(a, b)`
(shortest arc, `[0, RING_KM/2]`).

## Train placeholder (sim.js)

`sim.train = { x, v }` with `v = TRAIN_V` constant (0.1.3 replaces this with the
force model in `train.js`). `Sim.step` advances `x` by `v * dt` and wraps.
`Sim.reset` regenerates the world from the reseeded RNG and parks the train at
node 0. The sim owns no DOM and no camera.

## Camera + wrap-seamless rendering (render.js)

Side view: flat sky tone above `trackY = 0.74 * height`, flat ground tone
below, ties every `TIE_KM`, one rail line. `pxPerKm = width / KM_VISIBLE`.

The camera is stored **unwrapped** (`view.cameraX`, may exceed `RING_KM`) and
smooths toward the train anchor with `Render.cameraStep` (shortest-arc delta,
rate `CAMERA_FOLLOW`, follow clamped to 1). It snaps to the train on the first
frame and after a seed reset (`Render.snapCamera`).

An object at wrapped position `x` is drawn at
`x + round((cameraX - x) / RING_KM) * RING_KM` — the ring copy nearest the
camera (`Render.screenX`). Because the visible window (`KM_VISIBLE` <
`RING_KM`) is smaller than the distance between copies, the nearest copy
switches only while the object is off screen, so an object crossing `x = 0`
slides off one edge as its other copy slides in on the other: the seam is
invisible. Positions are stored unwrapped for the camera; wrapping is only for
lookup.

Nodes draw as a silhouette with a kind-colored cap (SRC amber, CON slate); the
train draws as a placeholder rect + cab, dimmed while paused.

## Files

```
js/world.js      new: wrap / distance / generate
js/sim.js        owns world + train placeholder
js/render.js     side view, camera, pure screenX / cameraStep / copyOffset helpers
js/main.js       passes sim + clamped frame dt to draw; snaps camera on seed change
index.html       adds world.js to the dep-ordered classic scripts; copy updates
experiments/world.js  new: spacing / determinism / shape / seam checks
```

Dep order: `rng, const, world, sim, clock, render, ui, main`.

## Check

`node experiments/world.js`:

- 100 seeds: every node pair at least `MIN_GAP_KM` apart (wrap distance),
  positions inside the ring;
- same seed twice → identical world arrays;
- shape: array sizes, exactly one inflow per SRC, CON recipe of 1–2 bits,
  positive caps / bases / rates, stock within capacity, at least one SRC and
  one CON, fragility in range;
- sim: the placeholder train steps across `x = 0` with the wrapped delta equal
  to `v * dt` every step, over a full lap;
- render helpers: every `(x, cameraX)` pair has a ring copy within
  `RING_KM / 2` of the camera; a following camera keeps the train on screen
  with no jump across the seam over multiple laps.

In the browser: switch seeds — nodes regenerate and the camera snaps; run at
8× — the world scrolls smoothly; cross `x = 0` repeatedly — no pop at the seam.
