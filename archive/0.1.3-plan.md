# 0.1.3 — train kinematics

Parent stage: `0.1.0-plan.md`. Scope: the placeholder train becomes a train —
mass, traction, power and resistance drive acceleration; it shuttles between two
waypoints the player picks, dwells at each end, and its trip time is predicted
in closed form before it departs. No money, no cargo, no tech sliders
(0.1.4 / 0.1.6). The only build knob wired now is the wagon count, because the
milestone check is about mass.

## Force model (train.js)

Per train per step, from `Const`:

```
build   = derive(g, d, e)          // knobs fixed at the starting build
M       = m_loco + W * m_wagon + cargoUnits * UNIT_T      // t
F(v)    = min(F_trac, P / max(v, V_EPS))                  // t·km/s²
F_res   = c_rr * M * TRAIN_G + C_DRAG * v³
a       = (F - F_res) / M
v       = clamp(v + a*DT, 0, v_track)
```

- Traction is limited by adhesive weight only:
  `F_trac = MU * DRIVE_SHARE * m_loco * TRAIN_G`. Wagons add mass, not grip, so
  an over-wagoned train leaves the station slowly. That is the mass-vs-speed
  story the rest of the game hangs on.
- Resistance is signed: when `F - F_res` goes negative the train *decelerates*
  instead of freezing. `v` is clamped at zero, never negative.
- `TRAIN_G` is a scaled gravity, not 9.8 m/s²: the visual band is 1–2 km/s, so
  adhesion and rolling resistance are scaled to put acceleration in the
  0.1–0.8 km/s² range. The unit set (t, km, s, t·km/s², t·km²/s³) stays
  internally consistent; it is deliberately not SI.
- A waypoint is captured by setting `v = 0` on arrival (the 0.1.0 plan defers
  the braking envelope to the torque model in 0.2).

## Trip profile and the closed-form estimate

The planner (0.1.5) must price a trip *before* it departs. Integrating per
planning call is banned, so the acceleration ODE is integrated **once per build
change** into three numbers — `profile{T, S, v}`: time to reach `v_track`,
distance covered doing it, and the cruise speed reached. Then:

```
estimate(L) = L <= S ? T * sqrt(L / S)
                     : T + (L - S) / v
```

Both branches are exact at the junction and asymptotically exact for long legs;
the only approximation is the shape of the accel phase, measured at ≤2.6% across
`L ∈ [0.5, 30]` km and `W ∈ [1, 8]`, and ≤2.3% over 6,000 arrivals in a
200-seed sweep (see Check). `Train.refreshProfile` runs whenever the wagon count
or cargo mass changes — never per step, never per frame.

A waypoint is captured inside the step that overshoots it, and the sub-step hit
time is solved from `km = v0·t + a·t²/2` and added to the trip clock, so the
measurement is not rounded up to a whole `DT`.

## State machine

```
WAIT ──set destination──> CRUISE ──arrive──> DWELL ──plan (swap A/B)──> CRUISE
  ↑                          │                  │
  └── clear route (click the node the train sits at) ──┘
```

- `WAIT`: no destination; `v = 0`. Reached only by clearing the route.
- `CRUISE`: `Train.advance` integrates `v` and moves `dir * ds`, wrapping at the
  seam. Arrival is captured inside the step in which the leg is covered, so the
  measured trip time is sub-step accurate; `v = 0`, `x = target`, `at = to`.
- `DWELL`: `dwellLeft` counts down from `DWELL_S`; at zero the waypoints swap
  (A↔B shuttle), the profile is refreshed, `tripEstimate = estimate(L)`, and the
  train departs.

`Train.advance(train, dt)` is the pure kinematics (force model + wrap) and
returns the distance covered; `Train.step(train, world, dt)` is the state
machine that consumes it. Experiments drive either.

## Train state

```
x, v, dir        position (wrapped km), unsigned speed, ±1 along the ring
state, from, to  WAIT/CRUISE/DWELL, waypoint node indices (-1 = none)
at               node the train is stopped at, -1 while cruising
dwellLeft        seconds left in DWELL
wagons           W, 1..8
cargo            Int8Array(WAGON_MAX), -1 = empty (filled in 0.1.4)
cargoUnits       count of loaded wagons, enters M
mass, profile    M and {T, S, v}, refreshed on build/cargo change
tripTime, tripEstimate, tripKm        current leg: elapsed / predicted / length
lastTripTime, lastTripEstimate,       copied at arrival and frozen there, so the
lastTripKm                            HUD reports a completed trip, not a running clock
```

`Train.advance(train, dt)` (pure kinematics: force model + wrap, returns km
covered) and `Train.step(train, world, dt)` (the state machine) are separate, so
experiments can drive the physics without waypoint logic.

`sim.trains` is an **array** (length 1 today); competitor trains are a 0.2
deferred feature and the plan reserves the shape now.

## Waypoints

One click, no sub-menu: clicking a node sends the train there from wherever it
is; on arrival it shuttles back to where it came from, forever. Clicking the
node the train is standing on clears the route and parks it (`WAIT`). Clicking
while cruising retargets: `dir` is recomputed from the current position and a
direction flip drops `v` to 0 (no teleport-turn). On reset the train parks at
node 0 and is given the nearest other node as its first destination, so a fresh
seed is always moving.

Direction is the shorter arc; a tie (exactly antipodal) goes to increasing `x`,
matching `World.distance`.

## Render (render.js)

- Train = loco + `W` wagon frames drawn behind it along `dir`, so the consist
  length is the visible mass. Wagons are empty outlines until 0.1.4 loads them.
- DWELL draws a progress bar above the consist filling over `DWELL_S`.
- Waypoints are marked on the track by `from` and `to`: a bright underline at
  the destination, a dim one at the origin.

## UI (ui.js, index.html, app.css)

- Footer gains a `WAGONS` range control (1–8) beside the telemetry group;
  `Main.setWagons` resizes the consist, refreshes the mass and profile in place.
- Telemetry gains `SPEED` (km/s) and `TRIP` (`measured/estimated` seconds of the
  last leg) so the 10% estimate check is readable in the page, not only in node.
- Copy, badge and the next-step card move to 0.1.3 → 0.1.4; the intro explains
  the click-to-route interaction.

## Check

`node experiments/train.js`:

- mass: `M = m_loco + W*m_wagon + cargoUnits*UNIT_T`, monotone in `W`;
- wagon sweep: measured trip time over a fixed leg is monotone in `W`, and
  doubling the consist (4 → 8) lengthens the trip by ≥15% (measured 4.02 →
  5.44 → 7.42 s over a 4.57 km leg for W = 1 / 4 / 8, i.e. ×1.37 for a
  doubling);
- estimate: for `W ∈ [1,8]` × `L` swept over 0.5–30 km, `|est - measured| /
  measured < 10%` (worst case logged);
- state machine: arrival sets `v = 0` and `x` exactly on the target, DWELL lasts
  `DWELL_S`, the waypoints swap on departure, clearing the route parks the train
  in WAIT;
- wrap: a leg that crosses `x = 0` arrives with the same timing as its mirror;
- cap and signs: `v` never exceeds `v_track` and never goes negative over a
  long run; a stalled build keeps `v = 0` instead of moving backwards;
- determinism: same seed and step count → identical `x`, `v`, state, trip clock.

`node experiments/harness.js` (extended): the 1× and 8× schedules now also
compare every train field and a world stock checksum.
`node experiments/world.js`, `node experiments/economy.js`,
`node experiments/boot.js` still pass; `node --check` on all scripts;
`git diff --check`.

In the browser: the train accelerates out of a stop, coasts up to its cap on
long legs, and crawls when the consist is long; drag the wagons slider and watch
the trip telemetry stretch; click a distant node and the train turns and runs
there; cross `x = 0` without a pop.
