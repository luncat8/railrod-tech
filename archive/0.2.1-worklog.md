# 0.2.1 — grade-aware movement

## Work

- Reviewed 0.2.0: the seeded height profile already moved the rendered track,
  stations and train, but it did not enter kinematics.
- Added signed grade force to powered acceleration:
  `F_grade = M · TRAIN_G · sin(θ)`. A positive slope rises along the loop and
  opposes traction; a descent assists it. The force scales with tare plus cargo
  mass, while locomotive adhesion and power remain finite, so heavy or weak builds
  lose more speed climbing and stronger engines can recover it.
- Each train step samples the terrain slope at its current position. The existing
  build-wide `v_track` remains the safety ceiling; braking still uses the existing
  service-braking envelope.
- Made the gauge, wheel and engine mass curves include the live cargo load. Wheel
  acceleration uses the live grade; the engine plot adds an acceleration-over-speed
  chart for the current, smallest and largest engines at that grade. Both
  acceleration plots display the grade at the train.
- Added deterministic checks for uphill/downhill speed change, grade-force scaling
  with mass, and the weak-versus-strong engine climb difference.

## Validation

All README experiments pass: `harness.js`, `world.js`, `economy.js`, `train.js`,
`trade.js`, `mass-balance.js`, `tech.js`, `plots.js`, `line.js`, `boot.js`,
`surface.js` and `gauge.js`. The line and sweep continue to use the same `Train.step`
rules; their replay, budget, conservation and performance-surface checks pass with
terrain active. Plot checks verify the live-grade acceleration values against
`Train.accel`.

## Next step

Make braking envelopes and any safety speed limits grade-aware before adding route
planning. The current model includes grade in powered acceleration but keeps the
existing service-braking rule and build-wide track-speed ceiling.
